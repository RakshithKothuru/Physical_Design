4. RTL — .v / .sv

RTL is the starting point of synthesis.

Example:

module alu (
    input  logic [31:0] a,
    input  logic [31:0] b,
    input  logic [2:0]  op,
    output logic [31:0] y
);
always_comb begin
    case (op)
        3'b000: y = a + b;
        3'b001: y = a - b;
        3'b010: y = a & b;
        3'b011: y = a | b;
        3'b100: y = a ^ b;
        default: y = '0;
    endcase
end
endmodule

RTL describes:

* functionality
* hierarchy
* registers
* combinational logic
* state machines
* interfaces
* clock/reset behavior

RTL does not normally describe:

* physical coordinates
* actual standard-cell placement
* routing
* wire parasitics
* final metal geometry

⸻

5. Gate-Level Netlist — .v

Synthesis converts RTL into a technology-mapped netlist

RTL

assign y = (a & b) | c;

Synthesized representation

        +-------+
a ----->|       |
b ----->| AND2  |---- n1
        +-------+
                     +------+
c ------------------>| OR2  |---- y
                     +------+

Example netlist:

module example (
    input  a,
    input  b,
    input  c,
    output y
);
wire n1;
AND2_X1 U1 (
    .A(a),
    .B(b),
    .Y(n1)
);
OR2_X1 U2 (
    .A(n1),
    .B(c),
    .Y(y)
);
endmodule

Netlist contains

* module hierarchy
* ports
* nets
* standard-cell instances
* connectivity
* instance names
* special cells

Possible cells include:

AND
OR
NAND
NOR
MUX
INV
BUF
DFF
Latch
Clock-gating cells
Tie cells
Isolation cells
Level shifters
Retention cells

Netlist does not normally contain

* exact cell coordinates
* routing
* metal geometry
* extracted RC

Those are introduced later.

6. Liberty — .lib

The Liberty file describes the electrical behavior of library cells.

Think:

.lib = What can this cell do electrically?

A .lib contains information about:

* logic function
* timing
* power
* area
* input capacitance
* output behavior
* timing arcs
* setup
* hold
* clock-to-Q
* recovery
* removal
* minimum pulse width
* transition limits
* fanout limits

⸻

6.1 Library-Level Information

Conceptually:

library(my_library) {
    delay_model : table_lookup;
    voltage_unit : "1V";
    current_unit : "1mA";
    time_unit : "1ns";
    capacitive_load_unit : "1pf";
}

This defines general library characteristics and units.

⸻

6.2 Cell Information

Example:

cell(AND2_X1) {
    area : 1.2;
    pin(A) {
        direction : input;
        capacitance : 0.002;
    }
    pin(B) {
        direction : input;
        capacitance : 0.002;
    }
    pin(Y) {
        direction : output;
        function : "A & B";
    }
}

Therefore the tool knows:

AND2_X1
 |
 +-- Logic function
 +-- Area
 +-- Input capacitance
 +-- Timing
 +-- Power

7. Timing Information Inside .lib

Cell delay depends on:

* input transition/slew
* output load/capacitance
* PVT condition

Therefore delay is normally represented using lookup tables rather than a single constant.

Conceptually:

                 Output Load
              0.01  0.02  0.05  0.1
Input Slew
   0.01         10    12    16    25
   0.02         12    14    18    27
   0.05         15    18    23    32

The table gives values such as:

* cell delay
* output transition

8. Timing Arcs

For:

A ----\
       AND ---- Y
B ----/

Timing arcs include:

A -> Y
B -> Y

For a flip-flop:

D ----> FF ----> Q
CLK --->|

The library can contain timing relationships involving:

D
CLK
Q

including:

* setup
* hold
* clock-to-Q
* recovery
* removal

9. PVT Libraries

Examples:

where:

Delay depends on:

Therefore different PVT corners require different characterization data.

12. create_clock

Example:

create_clock \
    -name CLK \
    -period 2.0 \
    [get_ports clk]

This defines:

Clock period = 2 ns
Frequency    = 500 MHz

The clock waveform and active edge can also be specified.

13. Input Delay

Suppose:

External Device
       |
       | data
       v
+---------------+
|   Your Chip   |
|               |
|       FF      |
+---------------+

The external device does not necessarily launch data exactly at the clock edge.

Therefore:

set_input_delay -max 3.0 \
    -clock CLK \
    [get_ports data_in]
set_input_delay -min 1.0 \
    -clock CLK \
    [get_ports data_in]

The delay is specified relative to the reference clock edge used by the constraint.

⸻

14. Output Delay

Suppose:

Your Chip
   |
   | data_out
   v
External Device

The external device imposes a timing requirement.

Example:

set_output_delay -max 2.0 \
    -clock CLK \
    [get_ports data_out]

This tells STA how much of the clock period is effectively available to the chip before the external receiver’s requirement.

⸻

15. Virtual Clock

A virtual clock has no physical port/pin.

Example:

create_clock \
    -name VCLK \
    -period 10

It can be used as a timing reference for interfaces:

External World
      |
    VCLK
      |
      v
Your Chip

Useful for defining input/output timing requirements independent of an actual clock pin.

⸻

16. Generated Clock

A generated clock is derived from another clock.

Example:

CLK
 |
 +---- Divider ----> CLK_DIV2

The SDC tells STA the relationship between the generated clock and its source clock.

17. UPF — .upf

UPF = Unified Power Format

UPF describes power intent.

It can specify:

* power domains
* supply nets
* supply sets
* power states
* isolation
* level shifters
* retention
* power switches
* shutdown behavior

Example:

                 VDD
                  |
        +---------+---------+
        |                   |
    DOMAIN_A            DOMAIN_B
     0.8 V                0.6 V
        |                   |
        +------ Level ------+
               Shifter

UPF describes the intended power architecture.

⸻

19. LEF — .lef

LEF = Library Exchange Format

LEF describes the physical abstract representation of cells and technology.

Think:

A standard-cell LEF can contain:

* cell dimensions
* cell symmetry
* site information
* pin locations
* pin shapes
* routing layers
* routing obstructions
* cell boundary
* physical properties

Consider:

The wire has:

+

+

It also contains interconnect effects.

           |
          C1
           |

34. TLU+ / ITF / Cap Tables

These files are associated with interconnect RC extraction.

The extractor needs to know:

Given a wire on this layer with this width, spacing and geometry, what are its R and C characteristics?

⸻

TLU+

Can provide technology-dependent RC models.

For example:

M1 -> R/C model
M2 -> R/C model
M3 -> R/C model
...

⸻

ITF

Interconnect Technology File.

Can describe:

* metal thickness
* dielectric information
* resistivity
* width
* spacing
* layer information

It can be used in extraction-model generation flows.

⸻

Cap Tables

Some extraction methodologies use capacitance tables to characterize interconnect capacitance.

Exact formats depend on the EDA tool and process.

73. Final Interview Cheat Sheet

If asked:

“What is .lib?”

Liberty is the electrical characterization of standard cells. It contains logical functions, timing arcs, delay/slew tables, setup/hold, power, capacitance and area information.

“What is LEF?”

LEF is the abstract physical representation of cells and technology used by physical-design tools for placement and routing.

“What is DEF?”

DEF describes the physical implementation of a particular design, including cell placement, nets, routing, blockages, rows and special nets.

“What is SPEF?”

SPEF contains extracted parasitic resistance and capacitance of routed interconnects and is used for accurate post-route STA.

“What is SDF?”

SDF contains back-annotated cell/interconnect delays and timing checks and is primarily used for gate-level simulation.

“What is GDS?”

GDSII contains the final physical geometry of the chip, including metal, vias, diffusion, poly and other mask geometries.

“Difference between LEF and GDS?”

LEF is an abstract physical view used during implementation; GDS contains the actual detailed physical geometry used for final layout/signoff.

“Difference between .lib and LEF?”

.lib describes electrical behavior; LEF describes physical geometry abstractly.

“Difference between DEF and GDS?”

DEF describes the implementation database—instances, coordinates, nets and routing—while GDS contains the actual physical polygons.

“Difference between SPEF and SDF?”

SPEF contains extracted R/C parasitics; SDF contains timing delays derived from timing analysis and parasitics for back-annotated simulation.
